# 펫 육성 개선 후보

초기 육성 흐름을 검토한 개선 후보입니다. 아래 후보는 아직 구현하지 않았으며, 현재 버전의 연결성 수정과 사용자가 다음 버전으로 보류한 범위는 [기능 연결성 검토](feature-flow-review.md)를 기준으로 합니다.

| 우선순위 | 후보 | 이유와 구현 방향 |
| --- | --- | --- |
| 1 | 일일 돌봄 미션과 꾸미기 보상 | 현재 쓰다듬기 이후 함께 할 행동이 적습니다. 기록 확인·짧은 놀이 등 하루 2~3개의 선택 미션으로 장식 재료를 주면 경험치 제한 이후에도 방문 이유가 생깁니다. 많이 먹거나 특정 음식을 먹도록 강요하는 미션은 피합니다. |
| 2 | 진화 추억 일기 | 현재는 발견한 형태 ID만 저장합니다. 진화한 날짜와 그때 함께 기록한 음식, 세대별 모습을 저장하면 사용자의 식사와 펫의 추억을 연결할 수 있습니다. |
| 3 | 방·모자·소품 수집 | 현재 외형 변화는 진화 단계와 계열 중심입니다. 도감 달성이나 돌봄으로 획득하는 소품을 추가하면 성장이 끝난 뒤에도 수집 목표가 생깁니다. 장착 상태는 성장 계열과 별도로 저장하면 됩니다. |
| 4 | 조건과 힌트가 있는 희귀 진화 | 현재는 미식 돼지를 포함한 다섯 계열과 17가지 형태가 기본 수집 목표입니다. 다음에는 여러 날에 걸친 식재료 다양성·돌봄 기록 조합으로 희귀 외형을 만들 수 있습니다. |
| 5 | 저장 관리 개선 | LocalStorage는 브라우저·기기마다 분리됩니다. 우선 마지막 백업 날짜와 백업 안내를 추가하고, 기기 간 동기화는 사용자가 원할 때 별도 서버 저장 기능으로 확장할 수 있습니다. |

## 이번에 반영한 기반

- 최근 7일의 식사 구성으로 다음 진화 계열 결정
- 끼니별 식재료 계열 중복 집계 방지 및 기존 일일 EXP 제한 유지
- 실제로 성장한 모습만 공개하는 17종 성장 도감
- 과거에 발견한 모습 유지 및 기존 저장 호환
- 1,000 EXP 이후 선택 가능한 새로운 성장 이야기
- 여러 음식 일괄 기록 시 저장과 보상이 마지막 항목으로 덮이던 문제 수정

## 검증

`npm run test:pet`는 진화 결정·끼니 중복·식사량·지난 날짜/간식·7일 범위·미발견 모습 비공개·기존 저장·세대 전환과 일일 한도를 검사합니다. 브라우저 렌더링과 실제 화면 조작은 별도 검증 대상입니다.
